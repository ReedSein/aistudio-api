# 账号登记与会话身份

`data/accounts/registry.json` 是已登记账号的元数据权威来源，包括名称、邮箱、子账号索引、Cookie 组和活跃账号选择。账号对象是不可修改的快照；修改统一经过 `AccountStore`，在一个锁内读取、创建新值并原子保存，磁盘成功后才发布内存值。解析失败明确报错，不能当作空账号库继续覆盖。

每个账号的 `auth.json` 保存登录凭据，临时文件以私有权限写入再原子替换。重新导入会更新内部凭据版本；旧页面刷新 Cookie 时核对该版本，防止把旧登录状态覆盖到刚导入的新凭据。重新导入失败时恢复原凭据，保留旧登记。

`meta.json` 只作为旧版本的兼容输入保留。启动时显式执行一次兼容检查，将有效的旧邮箱补入尚无邮箱的登记；不会覆盖登记中已有的邮箱、名称或子账号索引。普通列表、详情和活跃账号读取不写盘。兼容保存失败保留有效旧登记并报告失败，旧文件不删除。

单条、批量和探活导入都经过账号服务保存入口，并立即幂等登记到调度器。重复导入保留请求和额度统计，只解除认证失效状态。普通手动激活不清除模型冷却、限流记录或请求计数；认证故障恢复成功只解除相应认证冷却。管理界面的显式重置操作仍可按其原合同清除限额状态。

激活使用目标账号自己的凭据和登记快照。新页面完成准备后，活跃账号选择与就绪上下文连续发布；切换失败不将目标发布为可用账号。准备期间删除或重新导入目标账号时，凭据版本检查会拒绝过期的激活结果。

浏览器为每次新会话创建独立 BrowserContext，Cookie 不与旧会话或临时导入页面共享。旧会话等在途请求结束后再销毁。传输层只从所属页面获取签名 Cookie，不回读全局活跃账号凭据作为回退。

一次生成先取得并固定就绪上下文，再提取模板、计算快照、发送和收尾。捕获结果携带所属上下文，切号后重放仍指向该页面与子账号。成功、限流与错误统计使用本次实际账号；准备阶段还未取得账号时才使用已登记的选择。模板缓存切换上下文时在同一把锁内重新核验身份。

## 会员状态与手动刷新

账号列表、活跃账号和刷新响应新增三个可选字段：

| 字段 | 含义 |
|---|---|
| `tier` | `Free`、`Plus`、`Pro`、`Ultra` 或 `null`。`null` 表示尚未确认。 |
| `tier_checked_at` | 最后一次成功查询并保存的 UTC 时间；尚无成功记录时为 `null`。 |
| `tier_last_error` | 最近查询失败的稳定类别；成功刷新后清空。不会保存上游原文。 |

`POST /api/accounts/{account_id}/detect-tier` 使用现有管理鉴权，读取指定账号的凭据与子账号索引，向 Google 查询一次，成功保存后返回完整账号对象。该操作不会切换活跃账号。列表读取、浏览器准备、生成和后台轮询均不触发会员查询。

失败沿用管理接口的 `error.message` 响应结构。状态码为：账号不存在 `404`；查询期间账号被删除或凭据更新 `409`；上游限流 `429`；响应无法识别或上游认证失败 `502`；网络、凭据读取或持久化不可用 `503`。保存失败不得返回成功。错误类别包括 `rate_limited`、`authentication`、`invalid_response`、`unavailable`、`credentials`、`storage`；过期结果不会写回账号。

刷新失败保留最后有效等级和成功时间；有效的 Free 结果可以替换旧付费等级。新请求取得与会话凭据版本匹配的元数据快照，正在签名或发送的请求保持原快照。等级用于展示和请求头映射，不用于筛选账号或推断可用额度。管理页面在请求期间禁止重复点击，并在结果成功持久化后提示成功。

# 日志采集与诊断包

主服务、浏览器及 Termux 管理、安装、更新、清理和卸载过程默认记录排错日志。生成接口的请求与回复原文一并保存，包括原生思考部件、工具调用、工具结果与 thoughtSignature。静默启动只隐藏终端输出，仍保存诊断记录。

## 导出并反馈问题

出现问题后尽快导出，避免相关记录已经超过保留期限或容量。

- Termux 菜单：运行 `aistudio`，选择「导出诊断包」。
- 命令：`aistudio --export-logs`。
- 网页：打开控制台「系统设置」中的日志区域，点击「导出诊断包」。下载遵循当前控制台的管理鉴权。
- 油猴脚本：AI Studio 页面中的 Cookie 抓取面板点击「导出诊断包」，将浏览器摘要合入同一诊断包。需要脚本 0.1.3 及相应服务端；详见 [油猴说明](USERSCRIPT.md#导出脚本问题的诊断记录)。

命令导出默认保存在家目录，文件名为 `aistudio-diagnostics-时间-进程号.tar.gz`；网页使用浏览器的下载位置。指定命令导出位置：

```bash
aistudio --export-logs --output "$HOME/aistudio-problem.tar.gz"
```

已有文件不会被覆盖。将该压缩包和问题说明一起发送给维护者，说明出错的大致时间、当时做的操作、期望行为和实际现象；无需另行开启一次“正文捕获”。

**诊断包包含真实对话原文，可能有个人内容，请只发给信任的排错人员。** Cookie、认证密钥、密码、访问令牌和 BotGuard 票据按结构与已知格式脱敏；浏览器登录目录、账号凭据文件和 `.env` 原件不会装包。自然语言中的其他个人信息仍可能保留。

## 服务无法启动时

在项目目录执行，不要求服务、uv 或项目虚拟环境可用：

```bash
bash scripts/export-diagnostics.sh
bash scripts/export-diagnostics.sh --output "$HOME/aistudio-startup-problem.tar.gz"
```

系统 Python 可运行时使用与菜单、网页相同的导出核心。系统 Python 不可运行时，通过 Shell 和基础归档工具打包已保留的脱敏日志；此时使用 `manifest.txt`，明确标注依赖、配置和进程探测未完成。基础包与完整包都是 `.tar.gz`，不会伪装成环境检查已经成功。

安装命令会在下载安装器之前打印 `script-bootstrap-*.log` 的位置。即使下载失败、源码还不存在，也可以直接发送这个日志；取得源码后，同一日志目录中的记录会进入诊断包。

## 记录范围

| 来源 | 记录内容 |
|---|---|
| HTTP 请求 | 请求编号、时间、方法、脱敏地址和请求头、状态、耗时、结束原因 |
| 生成请求 | 完整请求正文、实际上游请求结构；BotGuard 票据脱敏 |
| 回复 | 非流式回复全文；流式分段、分段顺序、首包与总耗时、字节数和完成状态 |
| 应用运行 | 模块、进程、重试、浏览器就绪、账号/上下文切换与完整异常栈 |
| 浏览器 | 启动包装脚本、proot 和浏览器的标准输出、错误输出 |
| Termux 脚本 | 安装、下载、环境准备、启动、更新、清理和卸载阶段及失败退出码 |
| 油猴脚本 | 浏览器本地操作编号、版本、Cookie 项数与关键项缺失、请求回调/耗时/状态、回执解析与界面结果；不含凭据值或原始报文 |
| 探活导入 | 探活结果数量、保存阶段、逐项账号内部编号、已保存数量及异常；区分保存完成与 HTTP 发送状态 |
| 环境摘要 | 提交/发布版本、系统架构、Python/uv/关键依赖版本、预期浏览器版本、端口与必要磁盘信息、配置白名单 |

账号导入和配置等管理接口只记录操作元数据，敏感正文不会作为生成对话存储。静态资源和下载的诊断包也不作为回复原文再次采集。

正常运行不要求开启 `DEBUG` 或旧的 `logging.dump_requests`。这些旧调试设置控制附加终端打印与独立调试副本，不能关闭诊断采集；附加副本的自定义目录不属于诊断日志的轮换管理范围，建议仅在专项调试时使用。

## 保留与空间

默认保留最近 **7 天**，诊断日志预算 **512 MiB**。达到期限或预算时清理较早记录；日志分段轮换，清理情况写入诊断包。导出的压缩包由使用者自行管理，不随运行日志轮换删除。

Termux 默认日志目录为 `~/.local/state/aistudio-termux/logs/`，遵循 `XDG_STATE_HOME`。其他平台直接启动默认使用项目的 `server-logs/diagnostics/`。可通过环境变量调整：

```bash
export AISTUDIO_LOG_RETENTION_DAYS=14
export AISTUDIO_LOG_MAX_MIB=1024
# 可选：独立的私有子目录，不能是符号链接
export AISTUDIO_LOG_DIR="$HOME/.local/state/aistudio-termux/logs"
aistudio
```

天数范围为 1–3650，容量范围为 1–32768 MiB。在新的启动环境设置并重启，使用新值；离线导出也会读取日志目录最近生效的策略。Termux 管理脚本使用 shell 环境中的值；直接运行 Python 服务时，也可通过项目 `.env` 提供这些值。网页日志级别仅调整终端显示，不降低诊断记录的详细程度。

日志目录应为专用私有目录，权限为 700，日志与导出文件为 600。不会接管一个已有无关内容、却没有本功能管理标记的目录。

油猴的浏览器摘要独立存于脚本管理器，保留最近 7 天、最多 1 MiB、5000 条事件；其清理与存储错误随报告记录，也进入完整包的缺失清单。只在使用者点击油猴导出按钮时提交到服务；提交后的摘要随服务端日志保留策略管理，之后也可由网页或 Termux 再次导出。尚未提交的浏览器数据无法由服务端直接读取。

日志策略损坏或无法读取时，终端和网页状态会报告采集错误，采集暂停，业务请求仍可处理；不会用默认值悄悄覆盖坏策略。修正日志目录中的 `.policy` 或相关环境设置后恢复采集，暂停期间的缺口无法补回。

## 包内结构与分析顺序

完整包包含：

```text
README.txt
manifest.json
environment.json
logs/
legacy-*/          已识别、重新脱敏的旧 HTTP 转储，如存在
last-update.json   更新阶段记录，如存在
```

先检查 `manifest.json` 的采集截止时间、覆盖文件、摘要、缺失和清理说明，再对照 `environment.json` 确认版本及环境是否与问题相关。未知格式的旧底层报文不会原样装包，缺失原因会列入清单。

`logs/events-*.jsonl` 每行是一条事件。`request_id` 关联一次请求，响应头 `X-Request-ID` 返回同一编号；`session_id` 关联一个进程会话。请求处理、上游捕获及应用日志均携带该关联信息。

油猴每次操作的 `operation_id` 随 `X-Aistudio-Operation-ID` 请求头传入，服务端仅接受 32 位小写十六进制编号，作为辅助关联字段；请求编号仍由服务端独立生成。客户端编号不参与鉴权、去重或成功判定。`client_diagnostic_report` 保存浏览器摘要，`evidence_source=unverified_browser_report` 表示它来自客户端，需要与服务端事件交叉核对。

排查「脚本报错但账号已导入」时，先找同一操作的 `account_import_account_saved` 和账号内部编号，再检查 `account_import_saved`、`account_import_completed` 及 `http_end`。逐项保存记录可证明已落盘的数量；导入完成或 HTTP 发送完成均不证明浏览器已经收到并解析回执。浏览器的 `request_callback`、`request_settled` 和 `result` 可补足另一端的证据。日志有缺口时保留“无法确认”的结论，不据此自动重试导入。

生成正文以 `http_request_body` 和 `http_response_body` 的 `text` 字段记录，长正文分成多个 `part`，流式帧还带 `sequence`。按日志文件时间、文件内行顺序和这两个编号即可重组；结构化脱敏可能规范化 JSON 空白，但不会截掉非凭据的正文内容。

查找对应的 `http_end`：

| outcome | 含义 |
|---|---|
| `completed` | HTTP 回复发送结束；上游应用错误还需结合状态与正文判断 |
| `client_disconnected` | 客户端断开或发送连接失败 |
| `cancelled` | 请求任务被取消 |
| `timeout` | 等待或处理超时 |
| `exception` | 未处理异常；查看关联的 `http_exception` |
| `incomplete` | 未观察到完整回复结束 |

缺少 `http_end` 或 `response_complete=false` 不能判定为成功，可能是仍在进行、系统强杀或采集中断。磁盘写入、解析和归档失败会留下提示或缺失记录。功能启用前没有采集、已经清理、系统强杀前未落盘的内容无法恢复。

## HTTP 接口

- `GET /api/diagnostics`：返回日志位置、保留策略、文件数、总量及采集错误；遵循管理鉴权。
- `POST /api/diagnostics/export`：返回 `application/gzip` 附件；响应禁止缓存，不接受任意文件路径或待导出的文件名。原有空请求仍兼容；油猴可提交 JSON 对象中的 `client_report`，字段采用严格白名单，最多 5000 条事件，报告序列化后最多 1 MiB，原始请求体最多 1 MiB + 1024 字节。未知字段或格式错误返回 400，超限返回 413，客户端摘要无法保存返回 503；拒绝内容不会原样回显。

油猴未能下载完整包时，可下载标记 `kind=browser_only`、`missing=["server_diagnostics"]` 的本地 JSON。该文件仅有浏览器摘要，不含服务端日志；服务恢复后从同一油猴入口再次导出，合入仍保留的记录。

导出过程不会调用模型、导入 Cookie、自动上传或停止服务。服务可继续处理请求；包内截止时间之后的新记录留到下次导出。
